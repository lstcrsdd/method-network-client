# method-core-ffi — граница C поверх движка

Крейт переводит `method-core` на язык, который понимает Swift: целые
дескрипторы, плоские структуры, коды возврата. Решений не принимает и политики
не хранит — только переводит и стережёт границу.

Полное описание интерфейса, правило владения памятью и перечень кодов ошибок
живут в заголовке [`../include/method_core.h`](../include/method_core.h).
Заголовок написан руками и правится руками: генератор дал бы лишнюю зависимость
сборки и заголовок без единого объяснения.

## Сборка

```sh
cd Core
cargo build -p method-core-ffi --release              # target/release/libmethod_core_ffi.a
cargo build -p method-core-ffi --release --target aarch64-apple-ios
```

Тип библиотеки — `staticlib` + `rlib`. Статика потому, что приложение — один
бинарь: нечего подписывать отдельно и нечего искать в `@rpath` внутри бандла.

Дополнительных фреймворков компоновка не требует — хватает `libSystem`. Если
когда-нибудь появится зависимость от CoreFoundation или Security, это заметит
`tests/run_abi.sh`, а не тот, кто будет собирать приложение.

## Проверка

```sh
cargo test -q                              # ядро + поведение границы
sh method-core-ffi/tests/run_abi.sh        # сквозной сценарий на C
sh method-core-ffi/tests/run_abi.sh --release
MC_LEAKS=1 sh method-core-ffi/tests/run_abi.sh    # то же под leaks(1)
```

`tests/abi.c` собирается настоящим компилятором C из настоящего заголовка:
тест на Rust проверил бы только то, что Rust согласен сам с собой, а заголовок
мог бы при этом врать. Раскладка структур пришпилена числами по обе стороны
(`_Static_assert` в C и тест `раскладка_структур_пришпилена` в `src/ffi.rs`).

## Что важно знать интегрирующему

- **Время монотонное.** Все моменты — миллисекунды монотонных часов
  (`ContinuousClock`, `DispatchTime.now().uptimeNanoseconds / 1_000_000`).
  Стенные часы прыгают при синхронизации и после сна, а прыжок назад превратил
  бы остывание после переключения в вечный запрет.
- **Один движок — один вызов за раз.** Пересечение возвращает `MC_BUSY`, а не
  портит состояние. В Swift достаточно актора или своей последовательной
  очереди.
- **Подтверждать применение обязательно.** `mc_engine_reconcile` ничего не
  исполняет и ничего не считает исполненным. Пока не позван
  `mc_engine_lane_applied`, полоса для движка без маршрута, и следующее
  решение предложит выбор снова, начислив маршруту штраф за дребезг.
- **Состояние сохранять при выходе и загружать при старте.** Без этого каждый
  запуск даёт две-три минуты, когда все маршруты одинаково недостоверны и
  выбор фактически случаен.
- **Каталог поменялся — новый движок.** Дескрипторы действительны всё время
  жизни движка, удаления нет намеренно. Порядок такой: сохранить состояние,
  создать движок, объявить новый каталог, загрузить состояние обратно. История
  хранится по строковым идентификаторам и переживает это без потерь.

## Устройство

| Файл | Что внутри |
|------|------------|
| `src/abi.rs` | `#[repr(C)]`-структуры, строки как указатель+длина, константы |
| `src/error.rs` | коды возврата, текст последней ошибки в переменной потока |
| `src/engine.rs` | владение состоянием, которое ядро намеренно не держит; ни одного `unsafe` |
| `src/state.rs` | сохранение и загрузка истории измерений, пересчёт времени |
| `src/ffi.rs` | единственный файл с `unsafe`: `extern "C"`, ловля паник, дескрипторы |
