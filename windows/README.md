# Клиент для Windows

Состояние: **работает**. Туннель, подписки и интерфейс проверены на живой Windows,
установщик собирается одной командой. Чего ещё нет — подписи кода; что именно
готово, сказано ниже без округлений.

## Что должно получиться

То же самое, что на macOS, и ровно с той же моделью: клиент **для ваших
собственных** серверов. Пустой на первом запуске — узлы появляются из ссылок
(`hysteria2://`, `vless://`, `trojan://`, `ss://`) и из адреса подписки.
Встроенного каталога нет и не будет.

Один файл `Method.exe`: скопировал, запустил, вставил ссылку.

## Стек

| Слой | Чем | Почему так |
|---|---|---|
| Интерфейс | Avalonia 11 + .NET 8 | тёмная тема Method воспроизводится один в один и своими средствами; WinUI 3 тянет Windows App SDK в поставку и не живёт ниже Windows 10 19041 |
| Логика | C#, отдельная библиотека | разбор ссылок, подписки, сборка конфигурации и Clash API проверяются тестами без интерфейса и без туннеля |
| Туннель | `sing-box.exe` + `wintun.dll` | тот же движок и та же версия, что на macOS — расхождение в поведении между платформами дороже любой экономии |
| Права | служба Windows под SYSTEM | адаптер Wintun и таблица маршрутов требуют прав; служба ставится один раз с UAC, дальше интерфейс работает под обычным пользователем |
| Поставка | один самодостаточный `.exe` | движок и `wintun.dll` вшиты ресурсами и извлекаются при установке; распакованных папок с зависимостями рядом нет |

## Как это устроено

```
Method.exe (интерфейс, обычный пользователь)
   │  команды — именованный канал; трафик и состояние — Clash API 127.0.0.1
   ▼
Method.exe --service (служба MethodTunnel, SYSTEM)
   │  запускает и супервизит
   ▼
sing-box.exe + wintun.dll — TUN-адаптер, весь трафик системы в туннель
   ▼
Hysteria2 · VLESS+Reality (Vision и gRPC) · Trojan · Shadowsocks-2022
```

Один бинарь — три режима: интерфейс (по умолчанию), `--service`,
`--install` / `--uninstall`.

**Почему служба, а не запланированная задача.** Начинали с задачи под SYSTEM:
права она даёт те же и ставится одним движением. Отказались от неё по трём
причинам, и все три — про поведение, а не про красоту. У задачи нельзя спросить
состояние: «выполняется» означает «действие запущено», и упавший процесс от
незапускавшейся задачи не отличить. Задачу нельзя корректно остановить: снятие —
это убийство процесса, а убитый держатель туннеля оставляет за собой блокировку
исходящего трафика, то есть машину без сети. И задачи нет там, где выключен
планировщик, — на урезанных сборках Windows это обычное дело.

Служба называется `MethodTunnel`, работает под LocalSystem, поднимается при
загрузке и перезапускается системой при падении (через 5, 10 и 30 секунд). При
остановке — своей, или вместе с выключением машины — она гасит движок, убирает
адаптер и снимает блокировку. Установка поверх сборки с задачей снимает задачу.

## Чем это отличается от macOS

Одинаковой остаётся вся логика: разбор ссылок, модель профиля, сборка
конфигурации sing-box, подписки, оценка маршрутов. Различается только то, чем
поднимается туннель и чем рисуется интерфейс.

Отдельно стоит знать про TUN на Windows: стек `system` и `gvisor` ведут себя
по-разному под нагрузкой, и выбор между ними — замер, а не вкус.

## Оркестратор маршрутов

Движок выбора маршрута (`core/`) — общий, на Rust, с границей C. На Windows он
подключается статикой к отдельной библиотеке-обёртке и вызывается из C# через
P/Invoke. По плану очереди из корневого README это происходит после Android.

## Что готово

| Часть | Состояние |
|---|---|
| Модель профиля | четыре транспорта, формат записи общий с macOS и Android |
| Разбор ссылок | `hysteria2://`, `vless://`, `trojan://`, `ss://` (обе формы), подписные метаданные пропускаются |
| Сборка конфигурации sing-box | TUN и пробный mixed-инбаунд, каждая проверяется настоящим `sing-box check` в тестах |
| Привилегированная часть | канал, запуск и надзор за движком, kill switch, блокировка IPv6, урезание прав на рабочий каталог |
| Установка | режимы `--install` и `--uninstall`: служба от SYSTEM, правила брандмауэра, установка из интерфейса с запросом прав |
| Системный журнал | переломы видны в просмотре событий Windows под источником `Method`: туннель поднят и остановлен, движок упал, трафик заблокирован защитой, блокировку не удалось снять |
| Интерфейс | боковая панель и четыре раздела: обзор с циферблатом, серверы, сценарии, настройки |
| Хранилище профилей | зашифровано ключом текущего пользователя, запись через временный файл |
| Подписки | загрузка по адресу, автообновление, заголовки провайдера, форматы: ссылки, конфигурация sing-box, YAML от Clash |
| Задержка до узлов | замер по времени рукопожатия TCP |
| Восстановление | после сна, при смене сети и при тихой смерти движка |
| Значок в трее | два состояния, меню, закрытие окна прячет его туда |
| Статистика трафика | скорость, объём за сессию и график по данным движка |
| Флаги стран | рисуются полосами, узлы сгруппированы по странам |
| Оформление | два на выбор — основное и плакатное, переключается на лету |
| Настройки | сохраняются между запусками |

## Сборка

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```powershell
cd windows
.\Scripts\bootstrap.ps1          # приносит sing-box.exe и wintun.dll в Resources
dotnet build Method.sln -c Debug
dotnet test  Method.Core.Tests\Method.Core.Tests.csproj
```

Движок нужен и для тестов: часть из них проверяет собранную конфигурацию тем же
бинарём, который потом будет её исполнять. Без движка такие тесты не
пропускаются, а падают с указанием, что запустить, — проверка, которую
«пропустили», в отчёте неотличима от пройденной.

### Установщик

```powershell
.\Scripts\build-installer.ps1
```

Собирает `Installer\Output\Method-Setup-<версия>.exe`: клиент публикуется одним
самодостаточным файлом, рядом кладётся библиотека общего ядра. Нужен
[Inno Setup](https://jrsoftware.org/isinfo.php) — `winget install
JRSoftware.InnoSetup`.

Установщик ставит клиент в `%ProgramFiles%\Method` и передаёт установку
привилегированной части самому клиенту (`Method.exe --install`): службу,
правила брандмауэра и права рабочего каталога описывает он, и повторять это в
мастере значило бы завести второе описание того же, которое разойдётся с первым
при первой правке. Каталог установки не выбирается по той же причине — путь
зашит в самом клиенте, и выбор другого оставил бы файлы в двух местах.

Подписи кода нет: SmartScreen предупредит при первом запуске.
