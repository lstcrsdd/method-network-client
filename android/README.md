# Method для Android — клиент со своими конфигурациями

Тот же клиент, что на macOS: серверы кладёт человек, а не сборщик.

## Чем отличается от `Android/app`

`Android/app` — **старый** клиент, пакет `network.method.vpn`. У него серверы
вшиты в `assets/servers.json`, то есть пароли от нод есть у каждого, кто
распаковал APK. Он остаётся как рабочий эталон и никуда не девается.

`Android/client` — **новый**, пакет `network.method.client`. Приезжает пустым.
Разбор ссылок и сборку конфига делает общий слой на Rust — тот же код, что на
macOS и (со временем) на Windows.

Два пакета живут рядом намеренно: обновление старого не должно стирать людям
серверы, а сравнивать поведение нового удобно с работающим эталоном.

## Сборка

```sh
# 1. Общий слой под Android (нужен NDK, ставится sdkmanager 'ndk;29.0.14206865')
../../Core/Scripts/build-android.sh

# 2. Мост в Java
cd ../../Core && cargo build -p method-android --release --target aarch64-linux-android

# 3. APK
cd ../Android/client && ./build-apk.sh
```

Готовый файл: `dist/Method-android-debug.apk`.

## Что уже работает

* мост в общий слой — проверен на живом устройстве самопроверкой при запуске;
* добавление ссылок и подписок, хранилище без вшитых серверов;
* сборка конфига в схеме полос: пять осей обхода, блокировка вместо прямого
  выхода, когда живых маршрутов не осталось;
* подъём туннеля через `libbox` тем же способом, что в старом клиенте.

## Чего ещё нет

* **шифрования хранилища.** Профили лежат в настройках приложения: чужое
  приложение их не прочитает, а root и резервная копия — прочитают. На macOS
  это уже закрыто ключом, выведенным из машины;
* **оркестратора.** Конфиг с полосами собирается, но переключением осей пока
  занимается только само ядро группой `urltest`. Движок выбора к Clash API ещё
  не подключён;
* оформления. Экран намеренно голый: сперва доказать, что нижнее работает.
